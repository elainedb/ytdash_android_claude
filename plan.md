# Implementation Plan — YouTube Dashboard ("ytdash"), native Android

> Spec-Kit `/plan` artifact. The spec (`spec/spec.md`), acceptance criteria, and constitution are
> FROZEN. This document records the engineering decisions — the stack, architecture, and how each
> mandatory contract is honored — which is what the experiment measures.

## 1. Stack (and why)

| Concern | Choice | Rationale |
|---|---|---|
| Language / build | Kotlin 2.3, AGP 9.0.1, Gradle 9.1, `compileSdk 36`, `minSdk 29` | Generated by the official `android create` template; current idiomatic native baseline. AGP 9 has built-in Kotlin, so no separate kotlin-android plugin. |
| UI | Jetpack Compose (Material 3, BOM 2026.03) | The modern native toolkit; declarative UI maps cleanly onto unidirectional state. |
| State | MVVM with `ViewModel` + `StateFlow`, sealed `UiState` (Loading/Content/Empty/Error) | Constitution §1.3 (observable, unidirectional). Sealed states make every screen's loading/empty/error explicit and testable. |
| DI | **Manual container** (`AppContainer`) built per-Activity-launch | Dependency inversion (§1.2) without Hilt/KSP. Hilt on a brand-new AGP 9 toolchain adds annotation-processing risk for a 3-screen app; a hand-wired container is fully idiomatic here and lets the per-run `apiBaseUrl`/`apiKey` from launch extras flow straight into the network layer. |
| Networking | OkHttp + kotlinx.serialization | Lightweight, no codegen beyond the serialization compiler plugin; `Json { ignoreUnknownKeys = true }` tolerates the full YouTube payloads. |
| Persistence | `SharedPreferences` storing the video list as JSON | The cache contract is "replace-on-refresh + stale-fallback" (cross-framework-setup §D.1). A single JSON blob is the simplest store that satisfies it; Room would be over-engineering for one list. |
| Images | Coil (`AsyncImage`) | Idiomatic Compose image loading; thumbnails are best-effort (not asserted). |
| Map | **osmdroid** via `AndroidView` | The OpenStreetMap-native option for Android. Its markers are Canvas-drawn (no a11y nodes), which is exactly why the accessible affordance below is required. |
| Auth | Play Services Auth (`GoogleSignIn`, email scope) | Real Google sign-in for production; no `google-services.json` was provided in `config/`, so we use the Play-Services sign-in (verified email) rather than Firebase. The scored path uses UI-test-mode mock auth. |

## 2. Architecture (layered, constitution §1)

```
ui (Compose)            AppRoot → LoginScreen / HomeScreen / MapScreen
  │  observes StateFlow   AuthViewModel, HomeViewModel, MapViewModel
  ▼
domain                  Auth (whitelist), VideoQuery (filter/sort)  ← pure, unit-tested
  ▼
data                    VideoRepository (aggregate + dedupe + cache fallback)
  ├─ remote             YouTubeApi (OkHttp): search.list (paginated) + videos.list (locations)
  └─ local              VideoCache (SharedPreferences JSON), ChannelConfig (assets)
```

- **Single source of truth (§1.5):** the UI reads from `VideoRepository`, which returns the
  network result on success and the persisted cache on network failure. The disk cache is what
  makes the offline relaunch (AC-CACHE-01) work — a fresh process has an empty memory cache.
- **No UI-thread work (§1.4):** all network/disk in `withContext(Dispatchers.IO)` / `viewModelScope`.
- **Explicit errors (§1.6):** every screen renders `error_view` + `error_retry_button` on failure.

## 3. Data flow — fetch ALL channels, ALL pages (anti-overfit)

There is no catch-all endpoint. `VideoRepository`:
1. Reads the configured channels from `assets/channels.json` (synced from `config/channels.json` by
   a Gradle `Copy` task, so a rebuild always tracks the current config).
2. For **each** channel, calls `search.list` and **follows `nextPageToken` until exhausted**
   (the mock paginates with a tiny page size precisely to enforce this).
3. Tags each video's `category` with the **source channel's label** (config), per youtube-api.md.
4. Merges and **dedupes by `videoId`** (insertion order preserved; first channel wins).
5. Calls `videos.list` (batched ≤50) to attach `recordingDetails.location` (the map markers).

Nothing reads a fixture value: counts, ids, titles, and locations all come from the responses.

## 4. The three mandatory contracts

- **Selector contract (§3):** all ids are in `TestTags.kt`. `testTagsAsResourceId = true` is set
  ONCE on the `AppRoot` Box; every element uses `Modifier.testTag(...)`. The list-item id sits on
  the **title `Text`** (not the row) so id+text resolve to the same node (cross-framework §D.4).
- **UI-test-mode (§4):** `TestConfig.fromIntent` reads `uiTestMode`, `mockAuthEmail`, `apiBaseUrl`,
  `apiKey`, `authorizedEmails`, `captureExternalLinks`. Mock auth skips the picker; `captureExternalLinks`
  routes "open YouTube" to the `external_open_url` banner instead of launching.
- **Map markers (§5):** osmdroid pins are unreachable, so a native **`AssistChip` row** (one
  `map_marker` per located video, in the main composition) is the accessible affordance.
  `detail_bottom_sheet` is an inline `Surface` (NOT `ModalBottomSheet`, which is a separate window
  that breaks testTag→id — §5a). `map_marker_fallback_used = false`.

### Popup discipline (§5a)
No `DropdownMenu`/`Dialog`/`ModalBottomSheet` for any asserted element. Logout is a direct top-bar
action (no overflow needed). Filter/sort open **inline panels that replace the list** (so option
text can't collide with item titles), apply instantly (no apply button required), and live in the
main composition.

## 5. External-open correctness
`external_open_url` / `external_open_error` are lifted to the app root so one banner serves both the
list row tap (iteration 2) and the map sheet (iteration 4). In capture mode the banner text equals
the target URL exactly; the map sheet's `detail_video_url` is the same exact string, so AC-MAP-03's
copy-and-compare holds. In real mode, a failed launch surfaces `external_open_error` rather than
crashing (AC-LINK-01 verifies it does NOT appear when a browser is present).

## 6. Testing
- JVM unit tests: `AuthTest` (whitelist), `VideoQueryTest` (sort/filter/categories).
- Instrumented persistence test: `VideoCacheTest` (save/load round-trip).
- E2E: the 14 `flows/AC-*.yaml` against the mock.

## 7. Secrets
The API key is read at runtime from the `apiKey` extra; the build-time fallback comes from
`config/secrets.env` (gitignored), defaulting to `DUMMY_API_KEY` when absent. No secret is committed.
